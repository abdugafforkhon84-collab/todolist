## 🛠 Стек технологий

* **Backend:** Python 3.10+ / **FastAPI**
  * Модульная архитектура: `models/`, `schemas/`, `controllers/`, `routes/`, `middlewares/`
  * Авторизация: **JWT (JSON Web Tokens)** + хеширование паролей **Bcrypt**
  * ORM: **SQLAlchemy 2.0**
  * Валидация: **Pydantic v2**
  * CORS: Настроен для связи с клиентом
* **Frontend:** **React 18** (Vite SPA) + **PWA (Progressive Web App)**
  * Стиль: Минималистичный и светлый (яркий) дизайн
  * Иконки: Векторные SVG в черно-белой (*oq-qora*) стилистике
  * Offline-кэш и возможность установки на смартфоны/десктоп
* **База данных:** **PostgreSQL** / **SQLite** (по умолчанию `sqlite:///./crm.db` для моментального запуска в 1 клик без доп. настроек, переключение на PostgreSQL через `DATABASE_URL` в `.env`).
  * Готовые SQL-миграции в `database/migrations/`
  * Начальные тестовые данные в `database/seeds/`

## 📊 Модель данных и бизнес-логика

### Таблица `records` (Записи клиентов):
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| **`client_name`** | Текст | Имя клиента или название компании |
| **`phone_number`** | Строка | Номер телефона для связи |
| **`total_amount`** | Число (₸) | Полная стоимость услуги за выбранный срок |
| **`paid_amount`** | Число (₸) | Фактически оплаченная сумма на текущий момент |
| **`remaining_amount`** | Число (₸) | Вычисляемый остаток долга (`total_amount - paid_amount`) |
| **`period`** | Текст | Срок или даты оказания услуги (например, *«Ноябрь 2026»*) |
| **`task_description`** | Текст | Подробное описание задачи, которую необходимо выполнить |
| **`status`** | Enum | Системный статус: `Активно`, `Долг`, `Архив` |

### Автоматическое распределение записей:
1. **При создании или редактировании:**
   * Если `paid_amount < total_amount` ➔ статус **автоматически** становится `Долг`, запись сразу попадает во вкладку **«Долг»**.
   * Если `paid_amount >= total_amount`:
     * Если задача завершена или отмечена выполненной ➔ статус `Архив`.
     * Иначе ➔ статус `Активно` (вкладка **«Записи»**).
2. **Вкладка «Долг»:**
   * Отображает только клиентов с остатком задолженности.
   * Возле каждой записи выводится точная сумма долга и прогресс-бар оплаты.
   * Доступна кнопка **«Внести доплату»**.
   * При внесении суммы, закрывающей остаток долга, запись **автоматически переносится в «Архив»**.
3. **Вкладка «Архив»:**
   * Список завершенных и 100% оплаченных обязательств.
   * При необходимости запись можно восстановить обратно в активные в 1 клик.

## 🚀 Быстрый запуск (Локально)

> **Внимание:** Docker **не требуется**. Всё запускается прямо на вашем компьютере.

### Вариант 1: Запуск в один клик (Windows)
Просто дважды кликните по файлу **`start-all.bat`** в корне проекта.  
Он автоматически откроет сервер бэкенда и запустит клиентскую часть.

---

### Вариант 2: Запуск вручную через терминал

#### Шаг 1: Запуск Backend (FastAPI)
1. Откройте терминал и перейдите в папку `backend`:
   ```bash
   cd backend
   ```
2. Установите зависимости (если еще не установлены):
   ```bash
   pip install -r requirements.txt
   ```
3. Запустите сервер:
   ```bash
   python run.py
   ```
   *Сервер будет доступен по адресу:* `http://127.0.0.1:8000`  
   *Интерактивная документация Swagger:* `http://127.0.0.1:8000/docs`

#### Шаг 2: Запуск Frontend (React PWA)
1. Откройте второй терминал и перейдите в папку `frontend`:
   ```bash
   cd frontend
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Запустите dev-сервер:
   ```bash
   npm run dev
   ```
   *Приложение откроется по адресу:* `http://localhost:5173`

## 📱 PWA (Установка на телефон и рабочий стол)

Система полностью соответствует спецификации **Progressive Web App**:
* **Manifest (`manifest.json`)**: содержит настройки темы, названия и адаптивные векторные SVG-иконки.
* **Service Worker (`sw.js`)**: обеспечивает фоновое кэширование и работу интерфейса.
* **Кнопка «Установить»**: в навигационной панели при первом открытии в браузере (Google Chrome, Edge, Safari, Android, iOS) появляется кнопка установки. Приложение можно сохранить на главный экран мобильного устройства без необходимости публикации в сторонних магазинах.

## 🧪 Проверка тестами

Для верификации бизнес-логики и целостности эндпоинтов предусмотрен скрипт сквозного тестирования:
```bash
python backend/test_api.py
```
Тест проверяет:
1. Авторизацию и генерацию JWT
2. Сводную аналитику (общий долг, выручка, счетчики)
3. Создание записи с предоплатой ➔ статус `Долг`
4. Внесение промежуточной оплаты ➔ пересчет остатка
5. Внесение финальной оплаты ➔ **автоматический перенос в «Архив»**
6. Поиск и удаление записей.
